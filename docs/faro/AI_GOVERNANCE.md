# AI governance

There is no activated external recruitment AI provider in the Canonical runtime. New experience suggestions use `local-question-rules-v2` and are labelled as local rules in the workspace. Version2 requires complete normalized alias boundaries instead of arbitrary substring matches; e.g. administrative prose no longer proposes ADR and PostScript no longer proposes TypeScript. Historical v1 proposals retain their stored version and are not regenerated. Suggestions are persisted PENDING; only explicit candidate confirmation creates a DECLARED skill claim. Confirmation is not independent verification. Rationale is authored catalog text, never a copy of private activity/instructions; client-supplied provenance or verification cannot replace server-produced values.

Assessment creation accepts AI origin only as provenance. A submitted approval flag cannot make a definition published or assignable: create always stores DRAFT, review and conscious human approval precede assignment. Objective quiz scoring uses deterministic answer rules. The system does not auto-hire, auto-reject or produce a global candidate/potential score.

Future model adapters require minimized input, bounded output, schema/semantic validation, input/model/prompt versions, provider terms and a manual fallback. They must have no publication/decision capability. Free-text inputs and model output are untrusted data.

LEGAL BLOCKER for production recruitment AI/scoring until qualification, GDPR profiling/automated-decision assessment, DPIA and genuine human review are resolved. Source/legal review remains external evidence; this document does not claim legal clearance.
