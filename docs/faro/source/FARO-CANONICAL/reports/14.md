# UPDATED CROSS-PLATFORM UX & DESIGN CONTINUITY

FARO CANONICAL · 2026-09-16 · Polska · TARGET, nie deklaracja wdrożenia

## Wspólny produkt

Web/responsive/PWA jako rdzeń, Windows shell później po potwierdzeniu potrzeby; native mobile nie jest warunkiem publicznego nationwide startu. Tauri jest opcją, nie zatwierdzonym kosztem przed walidacją. Wersja mobilna nie może być okrojoną ścieżką wymagającą desktopu do udzielenia odpowiedzi.

Desktop: nawigacja + lista + szczegół zależnie od szerokości. Mobile: jedna kolumna, back zachowuje filtr i pozycję. Szczegół otwierany semantycznym linkiem z deep link; focus wraca do elementu po zamknięciu. Split-view nie oznacza ukrycia kluczowej akcji poniżej ekranu.

Candidate IA: Dzisiaj, Możliwości, Obserwowane, Moje procesy, Profil; porównanie z listy. Employer IA: Dzisiaj, Oferty, Rekrutacje, Assessment, Organizacja. Role przełączane jawnie; konto mające obie role nie miesza danych firmy z prywatną karierą.

## Action system

ActionItem zawiera owner, processId, type, dueAt, priorityReason, state, CTA. „2 firmy odpowiedziały”, „rozmowa jutro”, „zmieniono wynagrodzenie” to rzeczywiste zdarzenia, nie sztuczne zachęty. Zaległe zadanie firmy nie obciąża kandydata czerwonym alertem „działaj teraz”. Completed event zamyka task; retry wiadomości nie tworzy duplikatu.

Offer card: tytuł, firma, miejsce/model, płaca na właściwej podstawie, dwa–trzy konkretne powody zgodności i ewentualne istotne unknown. Primary CTA „Sprawdź ofertę”; w szczególe „Zgłoś zainteresowanie”. „Obserwuj” jawnie osobne. Nie używać „Wyślij CV”.

## Zachowanie identyfikacji

Zachowujemy Night #0B1020, Cloud #F7F9FC, Gold #FFC857 jako akcent, Manrope/Inter jako punkt wyjścia. Subtelne światło i kierunek, bez neonów i przeładowanego glass. Złoto nie jest kolorem drobnego tekstu na białym; kontrast trzeba mierzyć dla konkretnej pary. Statusów nie kodujemy wyłącznie kolorem. Nowy zakres nie uzasadnia sam w sobie zmiany logo ani employer sub-brand.

Tokeny semantyczne: surface/base/raised, text/primary/secondary, action/primary, border/default/focus, state/info/warning/error/success. Stan unknown nie ma czerwieni błędu kandydata. Skill level jako tekst i task anchor, nie pierścień87%. Wynik assessment może mieć procent z zakresem i breakdown, nie wizualną medalizację człowieka.

## Dostępność i wydajność

Cel projektowy WCAG2.2AA: klawiatura, logiczny focus, nazwy pól, błędy powiązane z polem, live regions dla zapisu i zmiany stanu, obsługa zoom/reflow, kontrast, dotyk i reduced motion. Nie stwierdzamy audytowanej zgodności gotowego produktu. Timer wymaga ostrzeżenia i legalnie właściwej obsługi sytuacji szczególnych; wyłączenie specjalnego modułu accommodations nie znosi tego obowiązku.

PWA cacheuje shell/publiczne bezpieczne zasoby, nie prywatne wyniki i employer roster. Offline pokazuje brak możliwości wysłania decyzji, nie fałszywe „zapisano”. Krytyczne operacje kolejki muszą mieć bezpieczną idempotencję i jawny status. Logout usuwa prywatne cache. Push nie zawiera danych wrażliwych na ekranie blokady. Zdjęcia marketingowe nie mogą być wymaganiem rozpoznania treści.

## Badania UX

Test z osobą bez doświadczenia, samoukiem, osobą po przerwie oraz małą firmą: zrozumienie źródła skill, brak CV, prywatność, dwa zegary, powód odmowy, diff i Start timera. Testujemy layout i copy, nie wariant łamiący konstytucję. Kryterium jest poprawne wykonanie i interpretacja, nie sam wybór „ładniejszego ekranu”.
