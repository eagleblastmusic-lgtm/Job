## Kontrakty prywatności

`EmployerCandidateProjection` budowany po stronie serwera przez jedną politykę dla API, PDF/eksportu, wyszukiwarki, maila i podglądu kandydata. Allowlist pól: processId, firstName, confirmed skill claims ze źródłem i kontekstem, task experience, learning interests, dostępność i jawnie udostępnione wyniki. Nie kopiować internal Candidate record i usuwać paru pól dopiero w UI.

Dowód może zdradzić tożsamość: portfolio, nazwa pliku, autor dokumentu, tytuł projektu, logo i URL. W MVP employer-facing dowód to kontrolowany opis/wyciąg bez historii firm i stanowisk. Surowe załączniki są prywatne; udostępnienie wymaga sprawdzenia projekcji i praw. Nie obiecywać pełnej anonimowości przy widocznym imieniu. Imię też jest potencjalnym sygnałem płci lub pochodzenia.

Grant telefonu ma `(candidateId, organizationId, processId, field, grantedAt, revokedAt)`; warunek etapu nie jest sam w sobie grantem. Cofnięcie blokuje przyszły dostęp, nie usuwa wiedzy już legalnie poznanej przez odbiorcę. O tym trzeba informować. Nazwisko w późniejszym etapie wymaga osobnej polityki; zakaz historii firm/tytułów pozostaje.

## AI jako adapter

Wejście minimalne → izolowana treść niezaufana → structured output → schema i walidacja semantyczna → propozycja/draft → człowiek → zdarzenie domenowe. Model nie ma narzędzi do zatwierdzania umiejętności, publikowania testu, zmiany etapu, billing ani odrzucania. Prompt nie jest granicą uprawnień. Nie wysyłać pełnej tożsamości, prywatnego netto ani historii kontaktu, jeśli zadanie ich nie wymaga.

Każda operacja zapisuje model/provider/version, prompt template version, schema version, czas, tokeny/koszt, wynik walidacji i wersję wejścia; bez raw PII w ogólnych logach. Cache rozdzielony tenantem i celem; brak globalnego cache odpowiedzi kandydatów. Retry tylko dla przejściowych błędów, z idempotency i limitem kosztu; fallback to ręczne wypełnienie, nie zgadywanie. Gemini jest możliwym dostawcą, nie koniecznym elementem domeny. Warunki API, przetwarzanie, wiek i transfery muszą przejść gate S12.

## Invariant ranking independence

Ranking input nie zawiera planu, przychodu klienta, etykiety premium, spend, ad campaign ani pochodnych. Billing nie jest JOIN-em w zapytaniu, cache key, tie-break, filtrem źródeł lub uprzywilejowaną pulą kandydatów. Płatne narzędzie nie może odblokować „lepszej” jakości algorytmu dla tej samej oferty. Test metamorfizmu zmienia wyłącznie plan firmy i porównuje wyniki, kolejność i dostępność.

## Security i niezawodność

RBAC plus przypisanie do procesu; osobne prywatne bucket keys, krótkotrwałe signed URLs po autoryzacji, brak publicznych CV/odpowiedzi. Admin break-glass z uzasadnieniem i audytem, nie cichy dostęp. MFA dla ról uprzywilejowanych, ograniczenia sesji, bezpieczne cookies, CSRF/XSS/CSP, upload limits i quarantine, zależności lockfile/SBOM. Obrona jest wymaganiem, nie potwierdzonym wynikiem pentestu.

Uruchamianie odpowiedzi kodowych/SQL wymaga odizolowanego wykonawcy z limitami zasobów, bez danych produkcyjnych, sekretów i zewnętrznej sieci. Nie uruchamiać w procesie API. Do czasu gotowości sandboxu: quiz/liczba/manual review; nie udawać automatycznego sprawdzania kodu.

Retencja musi mieć konkretną tabelę per cel przed produkcją. Propozycja do zatwierdzenia: transient AI input bez trwałego raw log; porzucone drafty po okresie nieaktywności; recruitment data do celu procesu i uzasadnionych roszczeń; wallet do wyboru użytkownika z niezależną retencją audytu; moderation evidence z restrykcyjnym dostępem. Nie przyjmować jednego 12-miesięcznego TTL dla wszystkiego. Wygaśnięcie retencji nie oznacza wygaśnięcia umiejętności. Usunięcie obejmuje indeksy, embeddings, cache i harmonogram wygaśnięcia backupów.
