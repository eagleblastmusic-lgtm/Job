# Faro standard — actual validation preparation

Run `node scripts/faro-skill-validation-packet.mjs` after build to generate a reproducible packet pinned to the entire catalog hash. `SKILL_VALIDATION_PACKET.json` is generated catalog diagnostics, not research. Alias collisions are hypotheses for semantic review; they do not create equivalence edges, claims, matching shortcuts or empirical relationships. Duplicate catalog IDs refuse generation. Existing exact-ID matching and independently confirmed claims remain authoritative.

For a real review, record the packet catalogHash, two catalog skillIds, relation (DISTINCT, POSSIBLE_OVERLAP or POSSIBLE_PREREQUISITE), reviewerReference, evidenceReference, studyScope and limitations in an access-controlled JSON file. `node scripts/faro-skill-validation-packet.mjs --review <file>` validates its schema/catalog references. References must identify actual materials and people outside the public repository. The tool does not verify reference authenticity and always reports REVIEW_RECORDED_NOT_EMPIRICALLY_VALIDATED and matchingEffect NONE. It never changes the runtime catalog or existing user declarations. Test fixtures are explicitly TEST_ONLY and are not accepted research records.

Independent reviewers must first define intended population/tasks, directional relation and use, sampling/consent/privacy procedure, assessment anchors, accommodations, comparison method and uncertainty reporting. Collect actual participant responses and independent judgments; record disagreements, false positives/negatives and version-specific limitations. Report missing evidence as unknown. No fixed participant count, validity threshold or confidence value is invented here; the appropriate study design requires competent reviewers. Only actual reviewed evidence plus explicit product approval can authorize a later empirical graph, migration/equivalence policy or assessment validity claim. Until then these remain EXTERNAL_BLOCKED.

No recruitment outcome is automated by this tooling. No raw candidate activity, CV, private contact or participant data is loaded or transmitted. Generated packet participants and empiricalResults are empty by construction. Public CI checks schema refusal, catalog pinning and the no-matching-effect boundary.
